## 风险台账

| 风险 | 影响 | 处理与触发条件 |
|---|---|---|
| 规则角落 | 看似能玩却非法 | perft+定向测试+差分；失败阻塞M1 |
| 完整死局识别 | 不等同简单子力不足 | 白名单先行；复杂局面算法单独评估，公开限制 |
| 引擎欠升变/过期结果 | 漏战术或误落子 | core完整升变、逐着核验、generation；M2 gate |
| 默认hash巨表 | 无法链接/OOM | 默认关，MAP断言；小TT必须patch与重测 |
| 24KiB pool | UI卡死/分配失败 | 一个棋盘对象、A8、无全屏canvas；量测峰值 |
| 单核同步搜索 | 输入卡顿/watchdog | worker callback deadline/yield/ACK；不关watchdog |
| 24KiB NVS压力 | GC/写失败 | 双槽≤6KiB压力测；需要时更改分区/迁移 |
| 掉电与保存延迟 | 最后一步丢失 | 已保存状态、双槽恢复、明确保证范围 |
| 中文字体/棋子授权 | 空白/侵权风险 | 精确字集、自绘/有授权资产与来源清单 |
| 上游漂移/文档频率差异 | 编译/显示退化 | 固定SHA，pin source优先，升级独立提交 |
| 完整镜像替换当前玩法 | 原有固件内容不再运行，NVS也可能因合并写入重置 | 标清 full 覆盖范围；提供设备专属官方恢复路径 |
| 启动器槽位兼容性未知 | 误装 full 可能覆盖原玩法或造成启动失败 | 先验证槽位协议、分区与退出方式，再发布槽位产物 |
| 合并镜像重置NVS | 棋局或其他配置丢失 | 发布说明、分段开发刷写、布局验证 |
| BLE“已有广告”误当联机 | 需求低估 | 新GATT协议与central角色，双机验收 |

## 待证据确认的决定

M0：CPU频率、SPI真实设置、最小RAM baseline、中文字体来源、BSP导入策略（推荐vendored必要文件而非整个demo）。M1：最大存档NVS压力与UI pool是否达标。M2：停止时返回结果语义、callback粒度、最大递归深度与棋力表现。每项保留记录，不以设计数字当测量。

## 后续协议/数据方向

谜题优先小批高质量一步杀/两步杀。Lichess数据许可在导入时重新核实，记录下载版本/校验和/题ID；公开答案线不保证唯一最优答案。验证合法同样杀法，双方应对不能简单播放固定线。题库Flash存储与进度NVS分离。

BLE不是沿用广播就完成：协议至少有版本/session、move seq、UCI promotion、规范局面摘要、ACK、去重、非法拒绝、重连全快照和角色约定。摘要只能做同步告警，不替代core合法校验。共享ADC不做双键快捷操作；无蓝牙Classic。

PGN先明确SAN生成、结果、升变/易位/将军后缀与编码。悔棋需恢复重复历史；重新开始搜索前递增generation。棋钟引入后另处理超时与不能将死规则，不能仅在footer加倒计时。社区玩法发布需单独授权并符合当前社区投稿要求，不因GitHub仓库创建自动投稿。
