## M1 功能验收清单

- 从初始局面进行一局本地双人；每一步只呈现合法棋子/落点；白黑交替明确。
- 长按可从升变/落点返回，不改局面；暂停继续、新局覆盖确认、返回首页继续上一局。
- 用户能完成指定e2e4，以及独立完成吃子、易位、升马；观察操作耗时，不预设所有着都只需几次按键。
- 同一设备重启仍保持side、castling、ep、halfmove/fullmove、history与结果；损坏档明确提示、未全擦NVS。
- 三次/50步申报与五次/75步自动终局一致，预选着申报入口可操作；终局后不能继续落子。
- 复杂死局尚未支持时，Release明确列出局限并阻止“完整FIDE规则”宣传；必需的走子与已列和棋门槛不能减项。

### 2026-10-07 自动休眠后恢复棋盘问题诊断

- 用户确认无操作 30 秒会变暗，但超过 5 分钟仍可见棋盘。被动串口捕获运行时间 `556146–556247 ms` 的电量计休眠校验、I2C 高阻、显示/背光保持和深度休眠日志，随后 USB 串口断开。用户仍看到棋盘；再次按键立即移动光标，串口时间已回到 `77213–77593 ms`。这确认设备在休眠流程后重新启动，不能把“进入休眠”日志作为持续休眠通过的证据。第二轮连续观察中，最后按键时间 `77593 ms`、进入休眠时间 `377723 ms`，间隔约 300.13 秒；USB 随即断开又重连，并捕获启动后 `759 ms` 的“象棋应用就绪”。观察期间没有人工按键，自动重新启动可复现；具体复位/唤醒原因码尚未捕获。
- 源码发现 GPIO0 同时用于 ADC 梯形按键和低电平深度休眠唤醒。ESP-IDF v5.5.3 的 [ADC 通道初始化](https://github.com/espressif/esp-idf/blob/v5.5.3/components/esp_adc/adc_oneshot.c)通过 [gpio_config_as_analog](https://github.com/espressif/esp-idf/blob/v5.5.3/components/esp_driver_gpio/src/gpio.c) 禁用数字输入，唤醒 API 不恢复该输入；原 BSP 未在休眠前恢复。这是与误唤醒相符的配置缺口，修正后仍需实机验证因果与持续休眠。
- `feature/idle-wakeup-fix` 本地修正先恢复 GPIO0 无内部上下拉的数字输入，间隔 20 ms 两次确认松开，再启用低电平唤醒。引脚/唤醒配置失败或检测到按键按下时，不关闭外设、不进入休眠。
- 新 BSP 回归在旧代码上因未恢复输入而失败；修正后，省电策略、应用集成、BSP 转换三项 ASan/UBSan 检查 PASS。
