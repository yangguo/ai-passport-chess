# AI Passport Chess 设计基线

日期：2026-10-06；状态：用户已确认主要方向，具体预算待实现与真机测量。

## 目标与方案

目标是口袋里的离线休闲国际象棋：开机能继续上一局；三键能完成每一种合法走法；搜索时仍能返回。第一阶段以规则正确和可操作为核心，不以引擎棋力作为验收指标。

方案比较：

| 方案 | 收益 | 成本/结论 |
|---|---|---|
| 自有纯 C core + 独立引擎 adapter | host 验证、完整升变、可替换 AI | 多一层规则转换；采用 |
| mcu-max 同时充当规则与 AI | 快速做出原型 | 当前欠升变缺失、状态全局；拒绝作为规则真相源 |
| 远程 AI/手机控制 | 棋力与操作可更丰富 | 网络依赖、配网与功耗；不纳入第一版 |

UI 使用 30+240+50 布局。以循环选择代替二维光标；落点去重，升变单独选择；合法列表来自 core。LVGL 采用一个自定义棋盘绘制对象加局部 invalidation，避免 64 个复杂对象挤占 24KiB pool。A8 图形仅存 Flash，绘制遵循当前 LVGL 版本的图片描述符，不使用全屏 canvas。

## 确定的产品决策

1. 初期本地双人、白方在下、不计时；不需要 Wi-Fi、BLE、音频。
2. 自动将死/逼和；三次重复与五十步是可申报和棋，五次重复与七十五步自动和棋。提供当前局面与预选着后的申报路径。
3. 保存已确认走法后的局面与必要重复历史；焦点移动不写 Flash。掉电只能保证最后一次保存成功的局面。
4. AI 使用独立快照、单 worker、generation 校验；任何越界、非法或过期结果都不会落子。
5. 不承诺完整比赛裁判功能：触子必走、处罚、棋钟、所有复杂死局识别另列限制，不能把“perft 通过”写成“完全符合所有 FIDE 条款”。
6. 发布提供 0x0 合并镜像、app 镜像、ELF/MAP、校验和、分区/版本/来源清单；记录设备验收。

## 数据流与错误处理

按钮事件 → 应用状态机 → core 合法列表/转换 → UI 快照 → storage 保存快照。AI 请求由应用传给 worker；worker 不调用 LVGL，不改真实棋局。存档只从应用获取不可变序列化快照。

初始化失败进入能显示/记录原因的错误页；存档损坏可从上一个槽恢复或新建，禁止无条件擦除 NVS；AI 失败采用已验证合法的保底着并记录降级。所有能力不足都显示实际状态。

实施与证据分开：文档检查、host 测试、ESP-IDF 构建、设备测量、用户操作验收各有独立结果。详见 [实施计划](2026-10-06-implementation-plan.md) 与 [验收标准](../acceptance.md)。
