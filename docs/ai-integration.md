# AI 与 mcu-max 集成

已接入 [Gissio/mcu-max](https://github.com/Gissio/mcu-max)，MIT；锁定 SHA 见[来源](sources.md)。原引擎不是本项目规则权威，不直接复制 micro-Max 默认资源设置。AI 与主机集成测试、固件构建已通过；设备预算及用户指定棋力目标尚未完成验收，见[开发状态](status.md)。

## 已核实的接口与风险

- `mcumax_set_fen_position` 返回 void，不提供输入校验；仅接受 core 导出的已验证 FEN。
- `mcumax_search_best_move(node_max, depth_max)` 同步运行；有内部加深逻辑。`mcumax_set_callback` 注册周期回调，回调中可 `mcumax_stop_search()`。
- `mcumax_move` 只有 from/to，没有 promotion 字段；头文件注明不支持 underpromotion。候选涉及升变时 adapter 明确附 Q，若 Q 非合法/不合产品战术需求则降级，绝不删除 core 中的 R/B/N。
- 引擎坐标采用从 FEN 第8行开始的0x88表示。核心 `a1=0` 转换 `((7-core_rank)<<4)|file`；不得误以为同一个 rank。a1/h8/双翼易位/ep 用测试验证。
- 状态是全局的，仅一个 worker 调用。FEN 每次搜索前重建，欠升变后仍能载入局面里的 N/B/R；不能靠连续调用 `play_move` 维持真实棋局。
- 源码 hash 默认关闭；启用时 `MCUMAX_HASH_TABLE_SIZE=(1<<24)`，不适合本设备。M2 保持关闭。日后小 TT 需显式补丁、编译期大小断言、链接 MAP 与实测，不仅翻转宏。
- FEN 能重建局面，不能传全部重复历史。引擎评分对重复/50步的理解需单独核实；应用终局与申报仍由 core 决定。

## 开局库（adapter）

在 `mcumax_search_best_move` 之前，adapter 用 `chess_position_key` 的 34 字节做
FNV-1a 64 位哈希，查一张编译进 Flash 的线性表（约 64 个局面、≤4 个加权候选）。
`book_seed == 0` 永远走权重最高的主变（host CLI / `tools/elo_match.py` 默认即 0，无需改 harness）。
产品新开局在 `start_ai_game` 时生成一次 `book_seed` 并整局保持不变；读档续走视为**已离开开局库**
（`book_enabled = false`，不改存档 schema）。库着法经 `chess_make` 复验，非法则退回搜索。
Easy 的 15% 随机着仅在离开库后生效。来源与再生成见 `components/chess_ai/BOOK_SOURCES.md`。

## 适配流程

1. app 生成不可变 position/FEN、合法根着、generation、预算；无合法着直接由 core 判终局。
2. worker 初始化并导入 FEN，注册带 context 的 callback，设置绝对 monotonic deadline。
3. 先保留一枚 core 合法的保底着；若开局库命中则直接采用库着，否则调用搜索，节点/深度仅作为第二道资源护栏，**时间截止是主限制**。
4. callback 以 clock 检查 deadline/cancel；按实测节奏让出 CPU（目标每2–5ms至少一次可阻塞 yield，不在每节点无条件 delay）。不能在 callback 里打印、绘制、写 NVS。
5. 返回转换坐标和 promotion；app 只有在 generation 相同、轮到AI、非终局时才检查精确合法着并提交。
6. 到达思考时限且存在完整层合法结果时正常返回最佳着；越界、无结果、引擎不支持、无完整层结果的超时及用户取消均有显式码；保底合法着只能在非用户取消且当前局面有效时采用。用户取消后不偷偷落子。

已增加本地补丁：在完整根层结束后保存最佳着，stop 时返回该检查点，未完成层不能覆盖；详见第三方 SOURCES.md。实际 callback 间隔、stop 后 unwind 时延与栈余量仍需在设备上测量。不得在每次外层加深重启后丢弃上一次好结果。

## 难度与提示（当前预算，棋力未经评级）

| 档位 | 墙钟预算 | 策略 |
|---|---:|---|
| Easy | 100ms | 正常搜索后小概率选择其他合法着；seed 可重放 |
| Normal | 1500ms | 最后完成层最佳着 |
| Hard | 5000ms | 相同规则，较长预算；不是“保证4层” |
| Hint | 400ms | 仅显示建议，不执行；玩家走后清除 |

mcu-max 不暴露多候选评分，不虚构 top-N 接口。Easy 初版随机从合法着采样；后续若需要“次优”，必须加 root scoring adapter 和测试。先做强制一步将死、避免一步被将死等核心战术 fixture；再以固定开局、相同种子/预算自对弈评估调参。不把四子棋 nodes/s 换算成象棋性能，也不凭深度声称 Elo。

## 实测强度基线（host，2026-10-08，430 局对 Stockfish 17.1）

**尺度说明：** 下表 Elo 均按 Stockfish 17.1 `search.h` 的 **CCRL 闪电战** skill→Elo 曲线换算（skill 0≈1347、3≈1729、5≈2197），表示与固定 Skill Level 对手的**分差**，**不是** Chess.com/FIDE/人类等级。用户指定的 Chess.com 快棋约 1200 仍为独立验收目标，**不能**用本表直接宣称“已达 1200”。

**方法（commit `b119fe6`，Release CLI：`cmake -S apps/cli -B build/cli-release -DCMAKE_BUILD_TYPE=Release`）：**

- 对手：Ubuntu `stockfish` 17-1（Stockfish 17.1），1 线程、16 MiB hash、Skill Level 0 或 3、每步 0.2 s（与 `tools/elo_match.py` 一致）。
- 规则裁判：`python-chess`；我方着法经 `chess-cli` 的 `ai` 命令（与固件同源 core 校验）。`play_game` 在可申报三次重复或五十回合和棋时结束；200 半回合上限判和。
- 430 局、0 中止/非法着/崩溃/超时；交替执白黑。终局：将死 342、可申报三次重复 63、200 半回合和 24、子力不足 1。
- 批量驱动在 `elo_match.Cli`/`play_game` 之上并行跑局；**Easy** 在主机侧模拟固件策略（搜索后 15% 概率改选其他合法着，约 7.2 次/局），因 CLI `ai` 尚无 Easy 子命令。Normal/Hard 使用下文“文档代用”节点/深度上限，**未**跑固件实设的 5M/8 与 20M/12（后者在主机上约 9 s/步）。

### 已废止：2026-10-07 小样本诊断（勿作当前结论）

| 我方配置 | 对手 | 比分 | 当时误读 |
|---|---|---|---|
| CLI 默认 200k/4 | skill 5 | 0/10 | “远低于 1200” |
| CLI 默认 200k/4 | skill 3 | 1/8 | 约 650–750（lore 锚点） |
| Normal 1M/8 | skill 5 | 0.5/6 | 约 780 |
| Hard 4M/12 | skill 3 | 1/6 | 约 720 |
| Hard 4M/12 | skill 5 | 0–2 后停 | 明显被动 |

废止原因：**仅 6–10 局/组**、曾用 **skill≈800/1000 的传闻锚点**（与 SF17.1 实测 skill 差约 380–400 不符）、早期 runner **未**在可申报和棋处停局、部分局在慢速 ASan 构建上跑。PR #5 起 harness 申报感知且拒绝在中止局上给评级；2026-10-08 大批次在 Release CLI 与 SF17.1 公式下重测，**取代**“host 天花板约 700–900”的结论。三档仍定位为让子阶梯（Easy 真让子 / Normal 休闲 / Hard 尽力）；追 Chess.com 1200 需换引擎或独立平台验收，超出当前 M2 范围。

提示及搜索不保存引擎全局内存。每次退出关闭 callback，确认 worker ACK 后释放数据。MIT LICENSE 与修改 diff 随集成提交，第三方版本升级重跑 adapter、deadline、perft（core 未变也测接口）与设备预算。

## 普通难度 Chess.com 快棋 1200 验收目标

用户指定参照为 Chess.com 快棋 1200；不等同于 FIDE、其他平台或
参考引擎的 UCI_Elo 设置。1200 是目标，不是当前评级。首先修正 deadline 引起的任意合法着降级，
再按设备实际吞吐测量完成层、节点、fallback 比例和响应时延。
普通/困难深度护栏保持 8/12，节点护栏分别为 500万/2000万；
增加时间预算不等价于达到指定 Elo。

评级需注明参考等级体系、对手和版本、用时、硬件与开局。建议使用
固定开局成对白黑交换对局，至少 100 局起步并报告胜和负与置信区间，
继续增加对局直到统计证据足够；有限测试不得称为保证 1200。
降低等级的参考引擎只能作工程对照，不能直接当作 Chess.com 快棋评级。
最终还需与该平台目标水平的棋手在明确用时下进行陪练评估，
不得为此自动登录平台或代用户发起线上对局。
战术测试、主机自对弈、ESP32 真机对局分别记录，不能混用结果。

本次回归：截止后保留吃后战术着；过早截止仍走合法 fallback；
取消不落子；普通结果合法性、一步将杀、避免一步被将杀继续检查。
Chess.com 快棋 1200 平台/陪练评级：NOT RUN；主机 CCRL 尺度成对对局（430 局）：**已测**（见上表）；新版预算设备时延/栈余量：NOT RUN。
